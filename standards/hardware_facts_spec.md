# STM32 硬件事实整理记录规范

**文件：** `standards/hardware_facts_spec.md`  
**版本：** v0.1

## 1. 目的与输出

本规范用于统一 STM32 开发板硬件事实整理记录的结构，为后续生成核心硬件上下文提供可靠、可核对的输入。

输出文件命名为 `<板卡设计编号>_hardware_facts.md`，存放在对应开发板的 `process/` 目录。不同开发板的记录数量可不同，但必须使用下述固定字段。

## 2. 文件结构

记录按以下顺序组织：

1. **硬件资料与目标信息：**
   简要列出开发板、目标 MCU、原理图设计 MCU、工程或变体，以及实际使用的参考网表、原理图和手册。设计 MCU 与目标 MCU 不同时，注明开发者确认的适用关系；不得自行认定兼容。
2. **表一：MCU 引脚映射表：**
   按第 3 节格式整理关键引脚。
3. **表二：板载硬件资源表：**
   按第 4 节格式整理关键资源。
4. **表间关联检查：**
   按第 5 节核对两表引用及主要连接事实。
5. **待确认事项：**
   记录资料冲突、配置条件不明、装配差异或证据不足的问题；没有则写“无”。

## 3. 表一：MCU 引脚映射表

字段名称及顺序固定：

| Pin | Net | Board Function | Connection | Condition | Status |
|---|---|---|---|---|---|
| `引脚号/引脚名` | 原始网络名 | 板级用途 | 相关器件和连接端点 | 焊桥、跳线、可选装配等使用条件 | 已确认 / 条件 / 待确认 |

要求：

- `Pin` 使用 `<物理引脚编号>/<引脚名>`，例如 `21/PA5`；同一引脚只能出现一次。
- `Net` 使用参考硬件网表中的网络原名，不擅自重命名。
- `Connection` 保留可核对的器件位号及必要端点；不要把逻辑功能当作物理连接事实。
- `Condition` 应写清已知的焊桥、跳线、可选器件和默认设置；没有明确条件时填写 `—`，不能凭网络端点推定器件已装配或线路已导通。
- `Status` 仅使用 `已确认`、`条件`、`待确认`，其含义见第 6 节。

## 4. 表二：板载硬件资源表

字段名称及顺序固定：

| Resource | Function | MCU Pins | Interface | Connection | Status |
|---|---|---|---|---|---|
| 资源名称或位号 | 板级功能 | 引用表一的引脚键 | GPIO / UART / USB / CAN 等接口类别 | 相关器件及配置连接 | 已确认 / 条件 / 待确认 |

要求：

- `MCU Pins` 必须引用表一的 `Pin` 键；多个引脚以分号分隔，如 `21/PA5; 44/PA11`。
- 没有直接 MCU 引脚的资源，`MCU Pins` 填 `—`，并在 `Connection` 说明实际关联。
- `Connection` 可包含必要的焊桥、跳线或可选装配条件，资源表不额外增列字段。
- `Status` 与表一使用同一取值规则。

## 5. 表间关联检查

整理结束后检查并记录：

1. 表一的 `Pin` 键是否唯一，格式是否符合要求。
2. 表一关键引脚的编号、引脚名与 `Net` 是否可在参考网表的 `mcu_pin_index` 和 `nets` 中核对；目标变体与设计基准存在差异时，另结合目标原理图、数据手册核对。
3. 表二所有非空 `MCU Pins` 引用是否均能在表一找到，列出无法匹配的引用。
4. 表二所述资源连接是否与表一及参考网表一致；资料差异列入“待确认事项”。

记录表一行数、表二行数、引脚引用数量及无法匹配数量。**不要求表一每个引脚都必须被表二引用**，也不要求所有 MCU 引脚均进入表一。

## 6. 事实依据与状态

- **已确认：** 连接事实有参考网表依据，板级用途或引脚功能有原理图、用户手册或 MCU 数据手册支持。
- **条件：** 连接或功能依赖焊桥、跳线、器件装配、模式选择等明确条件；记录资料给出的条件，不推断实板状态。
- **待确认：** 依据不足、资料矛盾或目标变体适用性尚未确认。

以标准化参考硬件网表为主要**连接**依据，结合目标变体原理图和手册确认板级功能与配置条件。保留必要来源、页码或章节以便追溯，但不改变两张核心表的字段。**原始网表包含某一器件端点，不代表该器件实际装配。** 对于手册与原理图位号不一致的情况，保留差异，不擅自改写。

## 7. 执行原则

- 优先重整已有硬件事实与已核对的参考资料，不因调整格式重新调用 MCP 或重新导出网表。
- 不为凑齐表格推测引脚、网络、外围功能和默认硬件配置。
- 两张表是核心成果；描述性文字尽量简洁，复杂问题集中放在“待确认事项”。
- 生成或修订记录时，保存实际操作指令、结果与简要结论；不得覆盖既有过程日志。
